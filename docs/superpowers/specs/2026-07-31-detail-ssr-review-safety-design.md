# 产品与新闻详情页 SSR 及评价结构化数据安全修复设计

## 背景与问题

2026 年 7 月 31 日部署后，网站首页、About 等普通页面可以正常刷新，但产品详情和新闻详情直接访问或刷新时返回 HTTP 500，并显示“Server Error”。同时，产品详情中的图片缩略图仍未出现。

线上检查确认：

- 两个不同产品详情地址均返回 HTTP 500。
- 新闻详情地址也返回 HTTP 500。
- About 页面返回 HTTP 200。
- 产品和新闻详情共同经过 7 月 30 日新增的动态 SEO 评价数据库逻辑；普通页面不经过该逻辑。
- 公网 HTML 仍引用旧前端资源 `index-CsZMcu56.js`，该文件已经返回 404；部署日志中的新资源为 `index-Cxzqkvw9.js`。

因此，本次需要同时解决详情页 SSR 的单点故障和部署后公网版本未对齐的问题。

## 目标

1. 产品与新闻详情页在评价数据或评价表异常时仍能返回正常页面，不能因为可选的 SEO 字段导致 HTTP 500。
2. 请求详情页时不再自动生成或写入评价数据。
3. 不输出虚假、自动编造或用户不可见的评价结构化数据。
4. 保留产品 `Product`、`Offer`、图片、库存、价格等有效结构化数据。
5. 保留已修复的产品图片缩略图功能。
6. 更新脚本必须验证详情页直刷和公网前端资源版本，避免“构建成功但公网仍使用旧 HTML/JS”。

## 非目标

- 本次不开发完整的客户评价后台、审核流程或评价前台组件。
- 本次不迁移或删除生产数据库中的历史 `seo_reviews` 数据。
- 本次不改动产品、新闻、翻译和上传文件等业务数据。
- 本次不调整无关页面的布局或视觉样式。

## 方案选择

### 采用方案：移除自动评价，保留真实产品结构化数据

- 删除详情页 SSR 请求链路中的自动评价生成和数据库写入。
- 产品 JSON-LD 暂不输出 `review` 和 `aggregateRating`；继续输出 `offers`。`offers` 已满足 Product snippet 的必要字段组合之一。
- 新闻 Article JSON-LD 不再附加产品式评价信息。
- 未来只有在网站收集到真实、经过审核、并在详情页可见的客户评价后，才重新加入 `review` 与 `aggregateRating`。

### 未采用方案

1. **固定数量和固定文案评价**：实现简单，但不是真实客户体验，也没有在页面上向用户展示，不符合 Google 对评价结构化数据的质量要求。
2. **保留数据库自动生成并只增加异常捕获**：可以避免 500，但仍会保留请求时写库、虚假评价和数据一致性风险，只隐藏故障而没有消除根因。

## 服务端设计

### 产品详情

产品详情 SSR 继续生成以下内容：

- Product 名称、描述、图片、品牌和制造商。
- Offer 价格、币种、有效期、库存、退货和运输信息。
- BreadcrumbList、FAQ 和服务端可读正文。

移除以下内容：

- 调用 `getOrGenerateSeoReviews`。
- 请求期间向 `seo_reviews` 写入数据。
- 基于自动评价生成的 `aggregateRating` 和 `review`。

### 新闻详情

新闻详情继续生成 Article 和 BreadcrumbList；移除自动评价查询、生成、写入以及 Article 中的评价字段。

### 故障隔离

评价属于可选增强信息，不得成为页面渲染的必要依赖。未来重新接入真实评价时，应通过独立的只读函数获取已审核评价；读取失败时省略评价字段，而不是使整个页面返回 500。

## 前端缩略图设计

保留当前 `ProductDetail.vue` 中已经恢复的绑定：

- 缩略图列表使用 `images` 计算属性。
- 缩略图按钮使用现有 `.thumbnail-btn` 样式。
- 当产品图片数量大于 1 时显示缩略图，点击后切换主图。

本次不再修改缩略图交互；部署校验负责确认浏览器能够取得包含该修复的新 JS 文件。

## 部署校验设计

扩展现有 `verifySeoDelivery.mjs` 和更新脚本的发布门禁：

1. 从公开产品 API 取得一个有效产品 slug，并验证本地与公网产品详情均返回成功 HTML。
2. 从公开新闻 API 取得一个有效新闻 slug，并验证本地与公网新闻详情均返回成功 HTML。
3. 提取本地和公网 HTML 引用的入口 JS 文件名，要求两者一致。
4. 请求公网入口 JS，要求返回 HTTP 200。
5. 任一检查失败时让 `server-update.sh` 明确失败，并输出不一致的地址或资源名，不能继续显示“更新完成”。

## 测试策略

采用测试先行：

1. 添加服务端源码回归测试，先证明当前代码仍包含详情请求时自动生成评价以及评价 JSON-LD。
2. 添加 SEO 文档测试，确认产品只含 Offer 时仍保留有效 Product JSON-LD，新闻 Article 不依赖评价。
3. 扩展发布验证测试，覆盖：
   - 产品详情返回非 2xx 时失败；
   - 新闻详情返回非 2xx 时失败；
   - 公网与本地入口 JS 不一致时失败；
   - 公网入口 JS 返回 404 时失败；
   - 所有页面与资源正常时通过。
4. 运行全部测试和生产构建。

## 发布与验收

代码推送 GitHub 后，服务器继续使用：

```bash
cd /www/wwwroot/steel-trader
bash server-update.sh
```

验收标准：

- 首页、About、至少一个产品详情和一个新闻详情直刷均返回 HTTP 200。
- 产品详情存在多张图片时显示缩略图。
- 公网 HTML 引用的入口 JS 与服务器本次构建一致，且该 JS 返回 HTTP 200。
- 产品 JSON-LD 保留 Product 和 Offer，不含自动生成的评价。
- PM2 日志不再出现详情页 SEO 注入异常。
