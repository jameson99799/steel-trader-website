# 第一批 SEO 安全修复设计

## 背景

线上审计确认了四个可以独立修复、且不需要改变产品、新闻、媒体或评价业务数据结构的问题：分类站点地图返回 HTTP 500；产品结构化数据发布了不真实的价格、运费和退货承诺；手机版产品缩略图在横向溢出时活动项可能位于屏幕之外；公开的 `llms.txt` 和 `llms-full.txt` 仍使用旧的 LED Trade 品牌。

本批次只处理这四项。多语言元数据、阿拉伯语 RTL、标题层级、首页视频和代码拆包在后续批次分别设计和验证，避免一次提交同时改变过多系统。

## 目标

- 分类站点地图在当前旧数据库结构和新安装数据库上都能正常生成。
- 产品页面继续输出 `Product`、真实公开 `Review` 和 `AggregateRating`，但不再输出虚构的 `Offer`、价格、运费或退货政策。
- 手机端通过主图箭头或点击缩略图切换图片时，活动缩略图始终能滚动到可视区域。
- 系统生成的旧 LED Trade 默认 AI 说明被安全迁移为 SUNSEA STEEL 内容，同时不覆盖管理员自行编辑的内容。
- 不删除、不重建、不清空数据库；不改变询价、邮件、WhatsApp、产品展示、评价管理和翻译功能。

## 方案选择

### 采用方案：小范围修复并为每项增加回归测试

每个问题先增加能复现当前错误的测试，确认测试因对应缺陷而失败，再做最小实现。四项修改分别验证，最后运行完整测试、生产构建和 SEO 交付脚本。

### 未采用方案：一次完成全部审计整改

一次同时修改站点地图、结构化数据、多语言、RTL、标题层级和性能，提交体积大，出现异常时难以定位，也不利于服务器安全回退。

### 未采用方案：把价格、运费和退货放入评价后台

交易政策和客户评价是不同的数据实体。将二者混合会让评价编辑权限影响商品政策，而且不适用于当前询价型 B2B 网站。未来确有公开价格时，应建立独立的产品报价与交易政策模块。

## 设计

### 1. 分类站点地图

`categories` 和 `news_categories` 目前只有 `created_at`，但站点地图查询了 `updated_at`。本批次不对生产数据库做表结构迁移，而是让分类站点地图及站点地图索引读取实际存在的 `created_at`。这样旧数据库和新数据库均可直接工作，不会写入业务数据。

测试覆盖：

- 分类查询不得引用不存在的 `updated_at`。
- 产品和新闻仍保留已有的 `COALESCE(updated_at, created_at)`，因为这两个表确实支持更新时间。
- 分类站点地图仍输出产品分类、新闻分类、语言版本和 hreflang。

### 2. 产品结构化数据

服务端 SSR 和客户端更新逻辑都删除整个 `offers` 属性。页面上的询价按钮、联系信息和产品可见内容不变。`Product` 继续包含名称、描述、图片、品牌、制造商、规格，以及经过公开审核的真实评价和汇总评分。

同时删除服务端仅用于生成伪价格的调用；如果生成函数没有其他用途，再由测试确认后移除未使用导入或函数。本批次不修改评价表、不删除评价，也不改变评价翻译和审核流程。

测试覆盖：

- 服务端 Product JSON-LD 不包含 `offers`、`price`、`shippingDetails` 或 `hasMerchantReturnPolicy`。
- 客户端 Product JSON-LD 同样不包含上述字段，避免页面水合后重新写回错误数据。
- `buildReviewSchemaParts` 仍被调用，评价与汇总评分保持原有行为。

### 3. 手机版活动缩略图

手机断点下将缩略图行由居中改为从左开始排列，消除 flex 溢出产生的负坐标区域。活动缩略图同步不再依赖元素级 `scrollIntoView`，而是根据按钮相对容器的位置计算目标 `scrollLeft`，并限制在 `0` 到最大滚动距离之间。这样只滚动缩略图容器，不会带动整个页面发生垂直或水平跳动。

保留图片/视频缩略图、前后循环切换、手指横向滚动和桌面/平板布局。缩略图按钮增加当前状态与可访问名称，但不改变视觉样式。

测试覆盖：

- 手机 CSS 使用 `justify-content: flex-start`。
- 定位逻辑写入容器 `scrollTo` 或 `scrollLeft`，目标值经过边界限制。
- 逻辑不再依赖无法处理负起点的 `button.scrollIntoView`。
- 图片和视频缩略图继续存在。

### 4. SUNSEA STEEL AI 说明

数据库初始化默认值直接改为 SUNSEA STEEL。针对已经部署的数据库，增加条件迁移：只有当 `llms_txt` 或 `llms_full_txt` 与系统历史 LED Trade 默认文本完全相同或明确以对应旧标题开头时才替换；管理员已经写入其他内容时保持原样。

新的 AI 说明只发布可核实的公司定位、主要产品类型和站内权威链接，不发布虚构认证、产能、成立时间或交易承诺。

测试覆盖：

- 全新数据库默认内容不再出现 LED Trade。
- 旧系统默认内容会迁移到 SUNSEA STEEL。
- 自定义 `llms` 内容不会被迁移覆盖。

## 数据安全与回退

- 站点地图、结构化数据和缩略图修改均为代码级变更，不写产品、新闻、媒体和评价表。
- `llms` 迁移只更新可精确识别的系统旧默认值，并在事务性数据库初始化流程内执行。
- 不执行数据库删除、重建、清空、批量评价生成或历史数据修正。
- 每项修复独立提交，服务器更新出现异常时可以回退到上一提交，数据库业务表不需要回滚。
- `server-update.sh` 的现有数据库备份与恢复流程保持不变。

## 验证

1. 对每项缺陷执行测试驱动的 RED-GREEN 循环。
2. 运行 `npm test`，要求全部测试通过且无失败。
3. 运行 `npm run build`，要求生产构建成功。
4. 运行 Node 语法检查和 `git diff --check`。
5. 本地启动生产服务，验证站点地图、产品详情刷新、JSON-LD、`llms.txt` 和手机版缩略图。
6. 只有全部验证通过后才提交本批实现；推送 GitHub 前再次确认提交范围。

## 验收标准

- `/sitemap-categories.xml` 返回 200 和合法 XML。
- Product JSON-LD 不再包含任何价格、运费和退货承诺，真实公开评价仍在页面和 JSON-LD 中保持一致。
- 390px 手机宽度下首张和后续活动缩略图均完整可见；桌面和平板功能无回归。
- 默认 `/llms.txt` 与 `/llms-full.txt` 使用 SUNSEA STEEL 品牌，自定义后台内容不会被覆盖。
- 产品、评价、翻译、新闻、媒体、询价和后台功能的现有测试全部通过。
