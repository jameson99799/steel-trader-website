# 产品缩略图自动居中设计

## 背景

产品详情页已经恢复多图缩略图，但通过主图左右箭头切换到缩略图条可视范围之外的图片时，下方缩略图条不会同步移动。用户看不到当前激活缩略图的位置，只能手动拖动横向滚动条。

## 目标

- 主图通过左右箭头切换后，当前激活缩略图自动平滑滚动到缩略图条中央。
- 从最后一张循环到第一张、从第一张循环到最后一张时保持相同行为。
- 点击缩略图切换主图时，激活状态与缩略图条位置保持同步。
- 初始化第一张图片时不产生不必要的页面滚动。
- 保留桌面端滚动条和移动端横向触摸滚动。

## 方案选择

采用 Vue 状态监听与 DOM 引用方案：

1. 为缩略图容器增加 `ref`。
2. 为 `v-for` 生成的缩略图按钮收集元素引用。
3. 监听 `currentImage`；值变化后等待 Vue 完成 DOM 更新。
4. 根据 `currentImageIndex` 找到当前按钮。
5. 仅当当前按钮不在容器的完整可视范围内时，调用 `scrollIntoView`，使用平滑动画并将按钮水平居中。

没有采用手动计算固定宽度的 `scrollLeft`，因为缩略图尺寸会随响应式断点变化；也不只使用 CSS `scroll-snap`，因为它不能响应主图箭头触发的状态变化。

## 组件修改

修改 `src/views/ProductDetail.vue`：

- 从 Vue 导入 `nextTick`。
- 新增 `thumbnailContainer` 和 `thumbnailButtons` 引用。
- 缩略图容器绑定 `ref="thumbnailContainer"`。
- 每个缩略图按钮通过函数 ref 按索引保存到 `thumbnailButtons`。
- 新增 `centerActiveThumbnail()`：比较按钮与容器的边界，只有按钮被部分或全部遮挡时才居中滚动。
- 监听 `currentImage`，在 `nextTick` 后调用同步函数。
- 路由切换或产品图片列表变化时清理旧按钮引用，避免引用上一产品的 DOM。

## 滚动行为

调用：

```js
button.scrollIntoView({
  behavior: 'smooth',
  block: 'nearest',
  inline: 'center'
})
```

`block: 'nearest'` 防止页面发生垂直跳动，`inline: 'center'` 让当前缩略图位于横向可视区域中央。

边界判断使用容器和按钮的 `getBoundingClientRect()`：按钮左边小于容器左边，或按钮右边大于容器右边时才触发滚动。当前按钮已经完整可见时不滚动。

## 异常与边界处理

- 图片列表为空、当前图片索引无效、DOM 尚未生成时直接返回。
- 浏览器不支持平滑滚动时由浏览器按普通滚动处理，不影响图片切换。
- 视频缩略图与图片缩略图使用相同按钮引用和定位逻辑。
- 单张图片不显示缩略图条，也不会触发滚动。

## 测试策略

采用测试先行：

1. 扩展 `test/productDetailGallery.test.js`，先断言模板包含容器和按钮引用。
2. 断言组件监听 `currentImage` 并等待 `nextTick`。
3. 断言滚动参数为 `behavior: 'smooth'`、`block: 'nearest'`、`inline: 'center'`。
4. 断言只有激活按钮超出容器水平可视范围时才调用滚动。
5. 运行产品详情目标测试、完整测试和生产构建。

## 验收标准

- 使用主图左、右箭头连续切换时，激活缩略图始终保持可见；超出范围时平滑移动到中央。
- 循环切换首尾图片时正确定位。
- 点击缩略图后，主图、激活边框和缩略图位置一致。
- 页面不会因为缩略图同步发生垂直跳动。
- 产品详情刷新、图片和视频缩略图原有功能不受影响。
