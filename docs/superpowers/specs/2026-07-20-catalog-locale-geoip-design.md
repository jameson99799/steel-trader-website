# 分类可见性、语言落地和客服 IP 识别设计

## 目标

在不改变现有产品、翻译、SEO 和客服流程的前提下：

1. 为每个产品分类提供独立的前台显示开关；关闭分类后，该分类、其后代分类及所属产品均不得在前台出现。
2. 在首次搜索落地时，根据访客国家跳转到已启用的对应语言；没有对应语言时使用英文。
3. 以可信代理解析、缓存和多级解析替换客服当前易误判的单一 IP 查询。

## 范围与非目标

- 仅处理产品分类 `categories`，不改变新闻分类、屋面板分类或产品自身的 `status` 语义。
- 不把数据库文件、GeoIP 数据库或 API 密钥提交到 Git。
- 不对管理员路由、API、上传路径和已记录语言偏好的访客进行语言跳转。
- 不修改人工语言选择、既有翻译内容及产品 slug。

## 分类可见性

### 数据和后台

- 在 `categories` 增加 `is_enabled INTEGER NOT NULL DEFAULT 1` 的兼容迁移，既有分类自动保持开启。
- 分类管理树的每一项显示开关。保存时仅更新该分类本身；关闭父分类不改写子分类的开关，以便重新开启父分类后恢复子分类原有状态。
- 切换成功后使分类相关的前端缓存失效。

### 统一前台规则

后端提供一个共享的可见分类解析器：分类必须自身开启，且从根到自身的所有祖先均开启。公开分类树会删除不可见节点，并删除没有可见产品或可见子分类的空节点。公开产品查询、公开产品聚合、产品详情、相关推荐、首页 SSR、产品详情 SSR、站点地图和客服快捷链接都复用此规则。

公开详情请求若产品属于不可见分类，返回 404；不会把隐藏产品当成可被发现的内容。前端只按公开 API 结果渲染，因此网格、菜单和侧栏会自然重排，不产生占位空白。

## 首次搜索落地的语言选择

### 优先级

1. 已记录的手动语言选择永远优先。
2. 仅当首次会话、请求来自外部搜索来源、且国家能映射到已启用语言时，进行一次临时跳转。
3. 无映射、无法可靠识别国家或目标语言未启用时，使用英文。
4. 不发生循环：目标语言与当前语言相同时不跳转；一次性偏好 cookie 记录自动选择结果。

例如印度访客首次从 Google 的 `/zh/products/...` 或 `/es/products/...` 结果进入，重定向至等价的 `/hi/products/...`。如果 Hindi 未在后台启用，则进入 `/en/products/...`。路径和 slug 保持不变。

### SEO 约束

- 每种语言继续使用独立且可抓取的 URL；现有 canonical 与全语言 hreflang 保持，并为每个页面输出已启用语言的互相引用及 `x-default`。
- 语言 URL 的正常直接访问仍可获取其原语言内容，确保 Google 可继续收录原有中文、西班牙语及其他语言页面。
- 自动跳转是面向首次搜索落地的人类会话体验，不用于为同一 URL 向爬虫返回不同内容；不能依据 User-Agent 假装或识别 Googlebot。
- 跳转响应使用临时重定向，绝不使用 301，避免搜索引擎把已收录语言 URL 视作永久迁移。

Google 仍建议优先让用户自行选择语言，因此需要保留页面中的语言选择器；本设计的自动跳转严格收窄到用户确认的搜索落地情形。

## 共享 IP 与国家识别

### IP 提取

- 新增共享网络识别模块，规范化 IPv4、IPv6 和 IPv4-mapped IPv6，并拒绝环回、私网、链路本地和无效地址。
- Express 只依据受信任反向代理后的 `req.ip` 提取客户端地址；不再将客户端可伪造的原始 `X-Forwarded-For` 或 `CF-Connecting-IP` 直接作为优先值。
- 部署文档说明 Nginx 必须保留 `X-Real-IP`、`X-Forwarded-For` 和单层受信任代理配置；若使用 Cloudflare，必须在 Nginx 层配置可信 Cloudflare 来源后再传递真实地址。

### 国家解析

- 国家解析为可复用服务，优先使用可信上游提供的国家码；每次请求设定严格超时。
- 以安全的内存 TTL 缓存按 IP 去重，正向与失败结果均短期缓存，避免客服高频消息阻塞或触发上游限流。
- 支持主服务失败时的后备服务，并以 ISO 3166-1 alpha-2 国家码作为内部值；用于客服展示时再映射成可读国家名。
- 聊天消息增加国家代码、解析来源和解析时间的兼容字段；历史 `country` 保留，确保管理端兼容。

语言落地与客服均调用这一个服务，避免两套识别规则产生不同结论。

## 错误处理和隐私

- 国家解析或网络失败时不影响发消息、页面加载或产品访问；客服显示“未知国家”，语言使用英文。
- 不记录查询供应商的原始响应，不向浏览器公开详细代理头。
- `/api/chat/debug-ip` 在生产环境移除或改为管理员可访问的最小化诊断信息，避免泄露请求头。

## 验证

- 数据库迁移：新旧数据库启动后默认开启分类，重复启动安全。
- 分类：分别验证关闭叶子、关闭父级、重新开启、公开列表、详情、首页、导航、SSR 和站点地图。
- 语言：验证印度到 Hindi、无匹配到 English、已保存手动选择不覆盖、非搜索链接不跳转、循环保护以及语言 URL/hreflang 完整性。
- IP：使用模拟请求覆盖正常代理链、伪造 `X-Forwarded-For`、IPv6、私网、超时、缓存命中与上游失败。
- 运行服务端语法检查、前端构建和针对新增公共逻辑的自动化测试。

## 部署

完成后仅提交源代码、测试和文档。推送到 `jameson99799/steel-trader-website` 的默认分支后，服务器按既有流程在备份数据库后执行：

```bash
cd /www/wwwroot/steel-trader
bash server-update.sh
```

部署后验证产品数量、聊天记录、PM2 日志、公开分类接口、印度/无映射国家的语言落地以及 Google Search Console 的 URL 检查。
