# 主页多语言首屏数据修复设计

## 背景与问题

主页的 Hero、推荐产品、产品分类、页面文字和公司信息都优先从服务端注入的 `window.__INITIAL_STATE__` 读取，以减少首屏布局跳动。当前服务端注入的是数据库原始记录，没有把当前 URL 语言对应的 `translations` 表内容写入对象。

前端发现这些首屏对象已经存在后，会跳过带 `lang` 参数的公开 API 请求。`localizedValue()` 找不到 `field_<language>` 时只能退回基础字段；Hero 和产品分类的基础字段目前是英文，所以中文及其他非英语页面会显示英文。静态 UI 字典不经过这条数据链路，因此标题、按钮和“个产品”等文字仍能正常翻译。

## 目标

- 直接访问任何已启用语言的主页时，首屏数据库内容立即使用该语言的翻译。
- 在站内切换语言时，所有主页语言相关数据同步更新，不残留上一种语言的内容。
- 英文页面继续使用原有英文字段。
- 某个字段缺少目标语言翻译时，继续使用现有回退规则，不显示空白。
- 保留服务端首屏注入和现有布局稳定性，不恢复为“先显示空白、再等待接口”的加载方式。

## 方案比较

### 方案 A：只让前端始终重新请求全部接口

实现简单，公开 API 已经能返回翻译。但会抵消首屏注入带来的性能和布局稳定收益，并产生重复请求，不采用。

### 方案 B：服务端只注入全部翻译表，由前端自行合并

可以避免后续请求，但会扩大 HTML 体积，并把服务端已有的翻译合并规则复制到浏览器，不采用。

### 方案 C：服务端按当前 URL 语言完成首屏翻译，前端切换语言时重新请求语言相关数据

直接访问时无重复请求、首屏即为正确语言；客户端切换时通过现有公开 API 获取新语言数据。该方案复用现有翻译函数，改动范围小，选为最终方案。

## 架构与数据流

### 服务端直接访问

1. 从 URL 前缀解析当前语言代码，例如 `/zh`、`/es`、`/fr`。
2. 继续使用当前请求范围内已经加载的 `tMap`。
3. 查询 Hero、页面文字、推荐产品和分类树。
4. 对非英语语言分别调用现有的 `translateHero()`、`translatePageTexts()`、`translateProduct()`、`translateCategory()` 和 `translateCompany()`。
5. 将翻译后的对象写入 `window.__INITIAL_STATE__`。
6. Vue 首次渲染直接读取包含 `field_<language>` 的对象，因此不需要额外首屏请求。

服务端需要把“构建主页首屏状态”的逻辑提取为一个可独立测试的函数，避免继续在大型请求处理器中堆叠不可测试的内联逻辑。该函数接收数据库读取函数、当前语言和翻译映射，返回主页需要的轻量状态对象。

### 客户端切换语言

语言变化后，主页并行重新请求以下数据：

- Hero
- 推荐产品
- 产品分类树
- 页面文字
- 公司信息

API 层现有的 `appendLang()` 会为所有非英语语言附加 `?lang=<code>`；缓存键也包含语言代码。`useLang()` 会在语言变化时清理公开 API 缓存，因此不同语言之间不会复用错误缓存。

主页使用一次统一的异步刷新函数更新上述状态。单个请求失败时保留当前已有内容并记录错误，避免整页清空；后续导航或再次切换语言仍可重试。

## 所有语言的适用规则

- 不硬编码 `zh`，除英语外统一使用当前已启用的语言代码。
- 翻译字段名称统一为 `<原字段>_<语言代码>`，与 `localizedValue()` 的读取规则一致。
- 语言是否可用仍由 `languages` 表中的启用状态控制。
- 数据库没有某字段翻译时使用当前回退顺序：目标语言字段、基础字段、英文字段。
- 品牌名、联系方式等现有规则明确不翻译的字段保持不变。

## 修改范围

- `server/index.js`：主页首屏状态改为使用语言感知的构建函数。
- `server/services/homeInitialState.js`：新增可测试的主页首屏状态构建逻辑。
- `src/views/Home.vue`：语言变化时统一刷新所有主页语言相关数据。
- `test/homeMultilingualState.test.js`：覆盖服务端首屏翻译、英语行为、缺失翻译回退和前端语言刷新契约。

不修改数据库结构、不重新生成翻译、不改变后台翻译流程，也不改动其他页面的展示设计。

## 错误处理

- 服务端某个可选列表查询失败时返回空数组，并保持页面可打开；核心公司、Hero 和页面文字查询继续使用空对象回退。
- 不支持的语言仍沿用现有 404 处理。
- 翻译映射为空时保留原始数据库字段，不生成空翻译字段。
- 客户端刷新失败时保留上一次成功数据并输出错误日志。

## 测试与验收

自动化测试必须覆盖：

1. 非英语语言会为 Hero、页面文字、推荐产品和分类注入对应的动态语言字段。
2. 两种不同非英语语言代码都能使用同一套通用逻辑，证明实现没有只针对中文。
3. 英语请求不需要翻译映射，仍返回英文数据。
4. 缺少某字段翻译时不会把原内容替换为空。
5. `Home.vue` 的语言监听会刷新 Hero、推荐产品、分类、页面文字和公司信息。

完成后运行完整测试和生产构建，并在本地生产模式中分别验证至少英文、中文和另一种已启用语言：直接刷新主页与站内切换语言后，主页数据库内容均使用对应语言。
