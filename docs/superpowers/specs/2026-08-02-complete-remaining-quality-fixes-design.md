# 剩余质量问题完整修复设计

## 目标

在不删除、覆盖或重写现有产品、新闻、媒体、翻译和评价业务数据的前提下，完成当前已确认的数据库初始化、favicon 兜底、前端图表体积、评价覆盖可见性以及全站多端验证工作，并为服务器更新提供可重复执行的自动检查。

## 范围

### 1. 翻译任务表安全初始化

- 在数据库初始化流程中幂等创建 `translation_tasks` 表。
- 字段覆盖现有翻译队列代码实际使用的 `target_lang`、`item_type`、`item_id`、`item_name`、`status`、`retry_count`、`error_message`、`created_at` 和 `updated_at`。
- 添加队列状态和任务去重所需索引。
- 仅创建缺失结构；现有表和现有记录保持不变。
- 使用内存数据库和生产数据库副本验证新库初始化与旧库升级两种场景。

### 2. favicon 稳定兜底

- 保留后台 `company.favicon` 或公司 logo 的动态生成逻辑，继续作为最高优先级来源。
- 将当前品牌 favicon 加入 `public` 静态资源，作为后台未配置或上传文件暂时不可用时的确定性兜底。
- 保证 `/favicon.ico`、`/favicon-16.png`、`/favicon-32.png`、`/favicon-192.png` 和 `/apple-touch-icon.png` 均能返回正确图像类型。
- 兜底不读取任意上传文件，避免错误地把产品图片当作网站图标。

### 3. ECharts 按需构建

- 将期货价格页面从 `import * as echarts` 改为 `echarts/core` 按需注册。
- 只注册页面实际使用的图表、组件、渲染器和特性。
- 调整 Vite 分包配置，避免强制把完整 ECharts 打入单一公共包。
- 保持期货走势图、K 线图、渐变和自适应缩放行为不变。

### 4. 真实评价覆盖统计

- 在评价服务增加按产品聚合的覆盖查询，分别统计已发布、待审核、隐藏和翻译数量。
- 后台评价页增加产品覆盖视图，支持按分类查看产品，并提示已发布评价少于 8 条的产品。
- 覆盖统计只反映数据库真实记录，不自动补数、不修改评分、不生成或发布虚构评价。
- 现有单条添加、批量导入、外部 API 待审核、批量发布和评价翻译流程保持不变。
- 同一条真实英文评价的不同语言翻译属于同一评价，不重复计入产品总评价数量。

## 全站验证

新增可重复执行的公开站点验证脚本：

- 从站点地图发现全部公开 URL，并检查 HTTP 状态。
- 对首页、产品列表、产品详情、新闻列表、新闻详情、关于、工厂、联系等页面模板执行 SEO 检查。
- 检查 `title`、meta description、canonical、hreflang、H1 和 JSON-LD 是否存在且可解析。
- 使用 390×844、820×1180 和 1440×900 三种视口检查页面横向溢出、运行时错误和主要图片加载失败。
- 服务器更新脚本继续使用现有 SEO 交付验证；新的完整检查作为发布后命令，不因外部网络瞬时失败而破坏数据库恢复流程。

## 数据安全和错误处理

- 所有数据库验证在副本或内存数据库上运行。
- 不删除现有表、列或记录，不执行数据库重建。
- 新迁移可重复运行，多次启动不会产生重复结构或重复数据。
- 评价覆盖接口只读；请求参数限制分页和分类范围。
- 自动检查失败时输出具体 URL、视口和检查项，并以非零退出码结束，不修改网站数据。

## 测试策略

- 按测试驱动方式先写失败测试，再实现最小修复。
- 数据库测试覆盖新库、已有任务表和重复初始化。
- favicon 测试覆盖动态来源、静态兜底和正确 Content-Type。
- 图表测试检查按需模块注册和构建产物不再出现完整 ECharts 大包。
- 评价覆盖测试覆盖产品无评价、不同状态、翻译不重复计数和分类筛选。
- 最后运行全部 Node 测试、服务器 JavaScript 语法检查、生产构建、数据库副本完整性检查和三视口公开页面检查。

## 发布边界

- 本批次只提交代码、测试、静态品牌图标和验证脚本。
- 不向正式数据库自动写入评价内容。
- 推送 GitHub 前必须确认工作区无无关改动，并核对远程 `main` 提交。
